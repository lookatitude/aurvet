## [0.0.1] — unreleased

The first tagged version. **Pre-1.0, alpha, not independently audited, not
signed.** It answers one question end to end: *is anything I installed from the
AUR known-malicious or provenance-anomalous?*

### What works

- **`aurvet scan`** — sweeps every installed foreign (AUR) package and reports
  provenance findings. On the reference system that is 39 foreign packages out of
  1410, in one batched AUR request.
  - `aur-tombstone` (**critical**) — the AUR removed this package's base *for
    malware*. The one near-definitive signal in the tool; an administrative
    removal such as a rename is deliberately **not** critical.
  - `aur-absent` (**suspicious**) — installed but absent from the AUR with no
    removal notice. The dropped-from-repo / renamed / never-published case.
  - `aur-orphaned` (**suspicious**) — no maintainer upstream; a takeover
    precondition rather than evidence of one.
  - `aur-submitter-mismatch` (**info**) — the current maintainer differs from the
    original submitter. Below the default reporting floor on purpose: it fires on
    roughly a third of a clean system, and a signal that common is noise until it
    can be correlated with *when* the handover happened.
- **`aurvet explain <id>`** — the evidence behind one finding, plus an explicit
  *"what this does NOT prove"* section.
- **`aurvet doctor`** — every resolved path with per-key provenance, so a
  misconfiguration can be traced to where it came from.
- **`aurvet version`** — the injected build identity, and an honest *"not
  injected"* when the binary was not built by the release pipeline.
- **Text and JSON output.** JSON carries `schema_version`.
- **Report persistence and `--since-last`** — diff a scan against the previous
  one to see only what changed. Stored under `$XDG_STATE_HOME/aurvet/reports/`,
  mode `0700`/`0600`.
- **`--offline-root`** — examine a mounted filesystem instead of the running
  system, for triaging a machine you have not booted.

### Design decisions you can observe from the outside

- **Coverage is reported, never inferred.** A check whose evidence is missing
  reports *unavailable* instead of passing. Exit `3` means "nothing found, but I
  could not finish" — and it **outranks** exit `1`, because a scan that found
  something *and* could not complete is still incomplete.
- **`--no-network` cannot produce a false clean.** With the network off the HTTP
  client is never constructed; the affected checks become coverage gaps and the
  run exits `3`. A network failure can never be read as "package deleted".
- **Exit codes are contractual**: `0` clean and complete · `1` findings at or
  above the floor · `2` bad invocation · `3` incomplete coverage.
- **`--min-severity` gates the exit code, not the display.** Below-floor findings
  are still printed, sorted last — the report never hides what was observed.
- **Statically linked, no third-party dependencies.** A dynamically-linked build
  could be subverted by `LD_PRELOAD` before it could report on
  `/etc/ld.so.preload`, which is a condition this tool rates critical.

### Release engineering

- Reproducible builds: two independent CI runners must produce byte-identical
  binaries or the release is not published. `SHA256SUMS` for every artifact,
  source tarballs from `git archive`.
- CI enforces the project's own invariants as merge gates — including the
  zero-dependency policy and a test asserting the binary is statically linked.
- Branch flow `dev → next → main`, with `main` force-push-proof.

### Known limits at 0.0.1

- **Packaging provenance only.** A clean result says nothing about whether the
  upstream *source* is malicious. A clean PKGBUILD fetching a backdoored release
  passes.
- **No file-integrity tier yet** — no mtree baseline, no `snapshot`/`diff`. Use
  `pacman -Qkk` alongside.
- **No release signing.** Artifacts are reproducible and hashed, but not
  OpenPGP-signed; the release key does not exist yet.
- **No AUR package**, and the `aurvet`/`-bin`/`-git` names are unregistered.
- The spec-required gate that aurvet's own PKGBUILD must pass aurvet's own
  indicators is **not implemented** — it depends on the PKGBUILD analyser arriving
  in P2.
