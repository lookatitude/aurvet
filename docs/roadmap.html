The ordering is dependency-driven, not preference. P2 precedes P4 because provenance evidence is ephemeral — 41% of foreign packages on the reference system already have none — so the capture mechanism must exist before a baseline records what it can see. P3 precedes P4 so the reproducible-build story lands before the project asks anyone to trust a signed chain.

Planning granularity — and why it differs by phase

✎

P1-A is planned to executable step level — 10 tasks, 50 steps, real test code, no placeholders (docs/superpowers/plans/2026-08-04-p1a-provenance-sweep.md). Every other phase is planned here to task level: exact files, exact interfaces, acceptance criteria, dependencies and risks.

That difference is deliberate rather than a shortcut. Step-level TDD detail commits to concrete function signatures, and for later phases those signatures depend on types P1-A and P1-B actually establish. Writing 300 speculative steps now would produce detail that reads authoritative and is wrong — the expensive failure mode this project has already been bitten by once. Each phase's step-level plan is generated at phase entry, against the interfaces that then exist.

What is fully decided here: scope, boundaries, file layout, interfaces between phases, acceptance gates, and every open decision. Nothing about what to build remains unplanned.

D-3 Capability handling for the privileged phase golang.org/x/sys/unix for capset/prctl. ✎

Resulting dependency policy. P1-A remains zero third-party dependencies — nothing in D-1…D-3 touches it. golang.org/x/sys enters at P1-B and is the project's only sanctioned dependency; go-git is conditional on D-1's fallback trigger and would require its own justification in the PR that adds it. P1-B · Integrity tier, staged privilege, TOCTOU-safe I/O

Goal: verify installed files against mtree digests, with all parsing running unprivileged and all I/O immune to path swapping.

#TaskFilesKey interface / acceptance
1mtree lexer — vis(3) unescapeinternal/mtree/unvis.goUnvis(string) (string, error). Table-driven over the full escape set. Measured: 379 lines / 599 occurrences on the reference system, mostly \040; unhandled, these become 382 spurious "missing file" findings.
2mtree parser — records and inheritanceinternal/mtree/parse.goParse(io.Reader) ([]Entry, error); Entry{Path, Type, Size, Mode, Time float64, SHA256, MD5, Link string}. Handles /set+/unset inheritance, float time=, md5digest (237 entries), and filters ./. metadata entries that do not exist on disk.
3Hostile-input boundsinternal/mtree/limits.goDecompression ratio cap and absolute ceiling — real data is 3–5× with a 5.7 MB max, so a 100× cap is far above legitimate use. Rejects missing #mtree header, truncated gzip, and any path containing .., absolute, or not ./-rooted (measured: 0 such paths exist, so any is damning).
4Confined file I/Ointernal/fsx/open.goOpenConfined(root *os.Root, rel string) (*os.File, unix.Stat_t, error) — open once with O_NOFOLLOW|O_NONBLOCK, fstat the fd, require S_ISREG. Never stat-then-open.
5Mutation detectioninternal/fsx/verify.goRe-fstat the same fd after hashing; a changed ino/dev/size/mtime yields mutated during scan.
6Privilege staging D-3internal/privdrop/drop.goReduceToRead() error then DropAll() error. Sanitises LD_*/GLIBC_TUNABLES and re-execs; sets PR_SET_NO_NEW_PRIVS; the drop clears the permitted set so nothing can be regained.
7Collect phaseinternal/collect/collect.goCollect(cfg) (Raw, error) — walk, confined opens, streaming sha256, buffer raw metadata. Measured budget ~41 MB. Contains no parsers.
8Panic and hang containmentinternal/safe/subject.goRun(subject string, fn func() error) (err error, panicked bool). Per-subject recover; every worker goroutine has its own; per-subject context timeout. A panic becomes a could-not-analyse gap (INV-9), never a global abort.
9Derived mutable-file exemptionsinternal/check/exempt.goParses installed pacman hooks' Target/Exec pairs to compute which files pacman itself regenerates — derived, not hand-maintained. Plus %BACKUP%. Must not blanket-exempt __pycache__: 103 packages ship digest-covered .pyc.
10Integrity checksinternal/check/integrity.goDigest mismatch; type=link compared as strings against recorded link= — never resolved-and-hashed, because 4,145 legitimate targets contain ..; unowned SUID/SGID.
11Performance tiersinternal/check/tier.gometa/triage/full/paranoid, full default. triage's prefilter reads its stat from the fd it would hash, and unconditionally hashes the security-relevant subset regardless of stat, carrying an mtime-assisted marker.
12Process-model assertionsinternal/privdrop/drop_test.goPost-drop read of a root-only file must fail; fifo and escaping-symlink fixtures refused not followed; mid-scan mutation detected; a panicking subject yields a gap with the scan completing and exit 3 — including from a worker goroutine.
13mtree conformance suiteinternal/mtree/conform_test.goFull escape set, inheritance, float times, metadata prefix, symlinks, hardlinks, corrupt gzip, traversal. Cross-validated against pacman -Qkk on a fixture root.
▲

Positioning constraint carried from the review: pacman -Qkk already performs sha256 verification and already exempts %BACKUP%. P1-B must not present file hashing as novel. Its justification is offline-root operation, parallelism, structured output, correlation input, and — the only genuinely new capability — supplying the mtree digests that P4's baseline uses to detect mtree tampering, which -Qkk structurally cannot do.

Gate: all 13 tasks green; conformance suite passes; zero criticals on benign fixtures with the integrity tier enabled; post-drop privilege assertion passes.

P1-C · Persistence surfaces and correlation

Goal: detect persistence planted outside package ownership, and tie host-side evidence back to packages.

#TaskFilesKey interface / acceptance
1Ownership oracleinternal/own/index.goIndex(pkgs []alpm.Package) *Owners and IndexIn(root *os.Root, …); Owners.Resolve(path string) (pkg string, State, error). Resolves symlinks so a package-owned target is recognised through a link. Amended in implementation: the originally specified two-value Owner(path) (pkg string, ok bool) was dropped. It cannot express the third state, so a failed resolution returned ("", false) — indistinguishable from genuinely unowned. Since this phase treats unowned as suspicious, every caller is one that would report a finding on the false, turning a coverage gap into a false accusation (INV-9). Three states, one lookup.
2Unit and timer parsing from diskinternal/surfaces/units.goParses unit files and *.wants/ links without systemctl — a compromised systemd cannot lie to it. Extracts ExecStart.
3The *.wants triage ruleinternal/surfaces/wants.goThree behaviours, not one: resolve symlink targets, exclude directories, alert only on unresolvable or non-package-owned targets. Measured on the reference system (/etc/systemd/system, 2026-08-05): 24 unowned paths → 9 *.target.wants directories, 14 benign enablement symlinks whose target is package-owned, and 1 link to a hand-written unit. Correction: an earlier revision said “30 → 19 + 8 + 1”, which does not sum (28) and was inconsistent; re-measurement gives the figures above. Treat the totals as a point-in-time snapshot — they drift with enablement state and installed set. The gate is the invariant: exactly one subject, and 0 broken links, both confirmed live.
4Hook directoriesinternal/surfaces/hooks.goCovers the system hook dir (57 hooks, active by default), /etc/pacman.d/hooks (absent on the reference system), and any HookDir override.
5Shadowed and disabled hooksinternal/surfaces/hooks.goNew check neither review caught: a package-owned hook can be disabled by a /dev/null symlink or shadowed by a same-named file in a higher-priority dir. Detects hooks suppressed, not only hooks added.
6Remaining surfacesinternal/surfaces/misc.gold.so.preload, generator dirs, profile.d, XDG autostart, per-user paths enumerated from the target's passwd — unreadable homes become coverage gaps.
7Correlation keysinternal/correlate/correlate.goThree keys: package; temporal (mtree time= ≈ %INSTALLDATE% ≈ transaction time — all inputs already collected); path attribution (resolve ExecStart, match directory or filename stem against foreign package names).
8System-state FP fixturestestdata/roots/{stock,cruft}/Extends the INV-8 gate with real system state — stock install and a cruft-laden root with pip, npm -g, manual /usr/local, hand-written units. Without these the gate is blind to its largest noise source.
9Incident acceptance fixturetestdata/roots/malicious/The CHAOS RAT structural shape — off-upstream source, scriptlet-installed unit, ExecStart to an unowned binary — must yield a correlated critical cluster. Inert markers only: no working payloads, no real C2 addresses.
◆

Severity ratings in this phase must be written down as weaker than they look. Correlation does not survive a competent attacker: a payload built into its own $pkgdir and shipped with an ordinary-looking unit produces no unowned files, a self-consistent mtree, and an ExecStart resolving to a package-owned binary. Every check in P1-C goes silent. This phase catches sloppy malware — the real incidents were sloppy, but needn't have been.

Gate: zero criticals on stock and cruft roots; the malicious fixture yields a correlated critical cluster; the *.wants rule produces exactly one subject on the reference system.

P2 · Pre-install gate and provenance capture

Goal: review a PKGBUILD before makepkg runs it, and capture ephemeral provenance while it still exists.

#TaskFilesKey interface / acceptance

2Git history reader D-1internal/vcs/gitlog.goHead(dir) (string, error), Log(dir, n) ([]Commit, error), Remote(dir) (string, error). Read-only; must not execute git against an attacker-controlled repo.
3.BUILDINFO and .SRCINFO readersinternal/pkgmeta/Extracts pkgbuild_sha256sum, builddir/startdir from a package archive; parses .SRCINFO for declared sources and deps.
4snapshot commandinternal/snapshot/, cmd/Captures PKGBUILD, .SRCINFO, .BUILDINFO, git log summary, remote, resolved source URLs, and the upstream commit built. Keyed on pkgbase — 433 of 1409 packages are split. A few KB per package versus the 88 GB cache holding the same facts.
5Bash tokeniserinternal/pkgbuild/lex.goHandles what real PKGBUILDs contain, measured over 34: array source=() (32), nested $( ) (2), heredocs (2), external source (2). Comment stripping is mandatory. Corrected label, not the number: this row previously wrote the fourth figure as ${var//x/y} (7), i.e. parameter expansion. The 7 is real and reproducible, but it counts command substitution — 7 of 34 recipes contain a command inside a $( ) (Command.SubstDepth > 0); the count is 8 for a bare textual $(, which also catches arithmetic and heredoc bodies. Parameter expansion is a different and definition-sensitive figure: strict ${v//x/y} substitution 1, any modifier form (// ## %% # % :-) 11, a modifier inside a source= entry 4, any expansion at all inside a source= entry 33. Quote the definition with the number.
6Variable resolutioninternal/pkgbuild/resolve.goResolves source_x86_64 / _aarch64 and parameter-expanded URLs. Emits Resolved or Unresolvable per value. Measured precisely during implementation, because "10 of 34 — a 29% blind spot" understates it in one direction and overstates it in another: 10 of 34 recipes use arch-suffixed sources, and dropping the per-target pass loses 56 of 145 source entries (39%), but only 2 of 34 (flux-bin, rustdesk-bin) lose every source. The other 8 also declare an unsuffixed source=() for icons, .desktop files and licences — so an unfixed resolver reports a completed review of the harmless half while never seeing the fetched binary, which is worse than reporting nothing. See internal/pkgbuild/resolve.go; expansion-count definitions are in row 5.
7Could-not-analyse verdictinternal/pkgbuild/verdict.goINV-9 made concrete. eval appears in 3 of 34 legitimate PKGBUILDs, including eval "package_$_p() { which generates the package functions — which is why zero cached PKGBUILDs contain a literal package_*() despite 31% being split. Unresolvable input is a coverage gap, never a critical and never silence.
8PKGBUILD rulesinternal/check/pkgbuild.goNetwork fetch in build functions (excluding comments and dependency arrays — both curl hits in the real corpus are false positives), writes outside $pkgdir, credential paths, privilege escalation, paste-site hosts, obfuscation, SKIP on fixed URLs.
9Dependency closureinternal/gate/closure.goResolves the full AUR dep closure and reviews every new PKGBUILD in it — the attacker's move is a benign package pulling a malicious dep. Prints the tree.
10Approval storeinternal/gate/approve.goKeyed on pkgbase + PKGBUILD digest: silent when unchanged, re-prompts on recipe change.
11VCS delta reviewinternal/gate/vcsdelta.goFor -git packages the recipe is stable while the source moves, so approving once would bless unbounded future commits. Shows the upstream commit range since the recorded snapshot.
12review and installcmd/aurvet/review analyses without building; install clones, reviews the closure, prompts, snapshots, then hands the vetted directory to the helper. Leads with rule hits and a diff against the last approved recipe, not the whole file.
13Hookspackaging/hooks/PostTransaction for provenance capture — the hook's genuine strength. PreTransaction shipped inert and warn-only: AbortOnFail is opt-in by one line, Exec routes through a path that always exists and no-ops when the binary is absent, so removal cannot brick pacman.
14Tokeniser fuzzinginternal/pkgbuild/fuzz_test.goSeveral thousand real PKGBUILD/.SRCINFO pairs asserting panic-free and hang-free, not correctness. The input is attacker-controlled, which is INV-2's justification.

Gate: dep-closure review working; pkgbase keying correct for split packages; VCS commit-range flow working; hook orphan-safety proven; fuzzing clean.

P3 · Packaging and distribution

Goal: make the tool installable in a way that does not require trusting its author.

#TaskAcceptance
1Reproducible build D-2Pinned toolchain (go.mod toolchain + GOTOOLCHAIN=local), vendored deps, -trimpath, -buildvcs=false, SOURCE_DATE_EPOCH, no injected build date. Two CI runners produce identical hashes.
2Static-link assertionA test asserts no DT_NEEDED/PT_INTERP. This is the deliberate deviation from Arch's Go guidelines, documented in a PKGBUILD comment: a dynamically-linked binary could be subverted by ld.so.preload before it can report on ld.so.preload.
3PKGBUILDSource package canonical; -bin only with options=('!strip'); release tarball is a git archive asset, never GitHub's auto-generated archive; SPDX license=(); arch=('x86_64' 'aarch64').
4Self-gateaurvet's own PKGBUILD must pass aurvet's own rules, enforced in CI. Note that without vendored deps build() performs a network fetch and trips its own critical rule.
5Release signingA second OpenPGP identity for artifacts, because makepkg only understands OpenPGP (validpgpkeys) — ed25519 alone gives AUR users no verification path. Fingerprint published in several independent places.
6AUR name defenceRegister plain, -bin and -git names on day one. Publish the canonical PKGBUILD upstream and have scheduled CI diff the live AUR copy against it — self-defence against takeover of this project's own package.
7systemd unitsScan unit with PrivateNetwork=yes, ProtectSystem=strict, ProtectHome=read-only, CapabilityBoundingSet=CAP_DAC_READ_SEARCH; update unit network-only. Timers with Persistent=true and randomised delay. Never enabled by .install — Arch policy.
8Failure notificationExit codes 1 and 3 both render as failed under systemd, which then tells nobody. Ship OnFailure= rather than masking with SuccessExitStatus=.
9Docs and completionsMan pages in scdoc (installed uncompressed — zipman is on by default), bash/zsh/fish completions with a test asserting every subcommand appears, tmpfiles.d for state dirs.
10Two-sided disclosureSECURITY.md whose in-scope list explicitly names false negatives — a false clean, a verification bypass, an evasion — as vulnerabilities. Plus docs/reporting-malware.md for the outward path, linked from critical explain output. Privacy statement: queries disclose the installed foreign package set; honour proxies, offer --no-network, never auto-update, no telemetry.
11CI hygienego vet, staticcheck, govulncheck, go mod verify, gosec, namcap, clean-chroot build from the tagged tarball, .SRCINFO sync assertion, and every action pinned by commit SHA — a supply-chain tool consuming mutable refs would be called out, correctly.

Gate: two-runner reproducibility diff identical; own PKGBUILD passes own rules; clean-chroot build succeeds; static-link assertion passes.

P4 · Baseline and trust chain hard ship gate

◆

This phase must not be enabled in any release until every task below passes. A baseline whose chain cannot be trusted manufactures confidence, which is worse than having none — this is the specific risk accepted when all four subsystems were kept in scope, and this gate is the mitigation. Partial P4 does not ship.

#TaskAcceptance
1Canonical serialisationSorted keys, no floats, fixed field order. Property tests: sign → flip any single byte → verify fails; reordering map keys must not change the digest.
2Key handlingOpenSSH ed25519 format, so ssh-keygen, ssh-agent and FIDO2 sk-ssh-ed25519 all work — INV-7 satisfied by hardware rather than discipline.
3Detached signaturesSignature over canonical JSON, deliberately not git commit signing, which would couple the tool to the user's git config.
4Manifest assemblyTwo-layer: stores sha256(mtree) per package, not per-file hashes — 1,410 records rather than 462,068, measured at implementation: 253,103 canonical bytes assembled in 291 ms, against ≥37 MB for the per-file alternative, roughly 147× smaller. (This row previously estimated ~325k per-file records, which understated the saving.) Includes provenance snapshot digests, surfaces inventory, adjudications, and the earliest pacman.log timestamp so later truncation is itself detectable.
5Hash chainprev_hash linkage; append, verify. Attack tests: truncated, forked, replayed, wrong prev_hash all rejected.
6Replication stateChain records pushed: bool; every run reports unpushed entries prominently. Documents that force-push and branch protection are load-bearing — "an attacker cannot rewrite remote history" is true only if the remote forbids it, and push credentials necessarily live on the monitored machine.
7Bootstrap refusalbaseline init runs a full scan and refuses to write while unresolved criticals exist; each must be adjudicated with a recorded reason. Refuses unprivileged. Refuses a triage-tier scan as its basis.
8Fingerprint epochsIndicators carry fingerprint_epoch; a change to matching semantics bumps it, and bound suppressions surface as stale — re-adjudicate rather than silently persisting or vanishing.
9Adjudication lifecycleThree scopes (pin/subject/rule), mandatory reason, default 180-day expiry, dead-suppression reporting. Distinct from the lightweight triage layer.
10pacman.log parsingExplicit RFC3339 offsets — the reference log mixes two (DST); [ALPM] lines only; rotated siblings read; entries naming another root (-r /mnt) handled; log coverage shorter than the baseline window is a gap, not a wall of criticals, and truncation is itself a finding.
11Drift classificationFour buckets: corroborated, adjudicated, unexplained (critical), log-coverage gap (reduced severity).
12Concurrency and crash safetyAdvisory lock; db.lck detected — scan warns, baseline append refuses, because reading a half-written DB mid-transaction produces spurious findings that would otherwise get signed. Temp + fsync + atomic rename; a payload without a valid signature reads as absent, not corrupt.

P5 · Indicator bundle

✎

Named "indicator bundle", not "rules". All non-trivial detection logic is compiled — ownership resolution, host comparison, tombstone corroboration, correlation, symlink handling. A network-delivered bundle carries only data: host lists, patterns, digests, thresholds, names, the rebuild-repo list. That is what threat intel is; calling it a rules engine would promise updatable detection capability the design cannot deliver.

#TaskAcceptance
1Bundle formatStrictly declarative (INV-1): no eval, no shell, no embedded scripting. Carries spec_version, monotonic bundle_version, valid_until, prior-bundle digest.
2Root key setEmbedded 2-of-3 offline, hardware-held. Signs only a delegation document.
3DelegationNames short-lived (30–90 day) online bundle-signing keys with expiry. Rotating the online key ships no new binary. Bundles cannot introduce keys.
4Anti-rollbackVersion floor held in root-only state, never the cache. A bundle below the floor is refused.
5Verification orderSignature verified over raw bytes before parsing. Size cap, timeout, no cross-host redirects.
6Fail-closed pathsExpiry ⇒ degrade to coverage-incomplete, never report clean. Retired root set ⇒ refuse with an actionable upgrade message. Report the active indicator count so a suspicious drop toward zero is visible — a bundle that removes detections is an attack.
7update commandNever automatic. --version prints root fingerprints, delegation expiry, cached bundle version.
8Attack suiteRollback, indefinite freeze, expired bundle, empty bundle, retired root — all must fail closed.
9Key-compromise runbookdocs/key-compromise-runbook.md, written before first release, not after an incident.
