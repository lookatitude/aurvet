aurvet — design specification

Detects compromised AUR packages and verifies an Arch system has not been infected. Four subsystems on one evidence core.

● Draft for review 2026-08-04 Go · Arch Linux supersedes the reviewed design

1 · Scope

A Go CLI answering two questions: am I compromised by a malicious AUR package, and has anything changed that pacman did not change. Four subsystems, all in scope:

SubsystemCommandsPurpose
Forensic sweepscan explain doctorAm I infected now?
Pre-install gatereview install snapshotShould this build run? — and capture provenance while it exists
Drift baselinebaseline diffWhat changed that pacman didn't do?
Indicator bundleupdateWhat is newly known-bad?

All three verbs are the same operation against different reference points: scan compares live state to expectation, diff to recorded state, review to indicators. That is why one core serves all four.

Non-goals: judging whether upstream source code is malicious; replacing rkhunter/AIDE/EDR; multi-distro support; performing remediation (it reports, explains, and gives investigation commands — the operator acts).

▲

Recorded concern, overridden by decision. The design review recommended a reduced first milestone, on the grounds that the baseline is actively harmful when half-built — a chain you cannot fully trust manufactures confidence — and that the indicator bundle is largely superseded by the AUR tombstone check (§5), which needs no curation. All four subsystems are retained by operator decision. §17 therefore places an explicit ship gate on the baseline: it must not be enabled in a release until its full acceptance set passes, precisely so the half-built state cannot reach a user.

3 · Architecture

cmd/aurvet          CLI wiring, flag parsing, exit codes

internal/inventory      local DB reader: desc, files (incl. %BACKUP%), mtree, install
internal/provenance     helper-cache git history, .SRCINFO, .BUILDINFO, AUR RPC + cgit
internal/pkgbuild       bash-aware tokeniser + analysers; emits resolved | unresolved
internal/surfaces       units, timers, hook dirs, ld.so.preload, rc, autostart, SUID
internal/indicators     declarative matcher over evidence; bundled + updatable data
internal/baseline       canonical serialisation, ed25519, hash chain, replication state
internal/report         findings, severity, correlation, coverage accounting, JSON

Collectors are pure functions of (root, cfg) (INV-4). --offline-root PATH is a prefix threaded through them, not a second code path. Four documented deltas in offline mode, enumerated here because the equivalence test (§15) cannot be written without them:

  1. No live systemd — unit files and *.wants/ links are parsed from disk, never via systemctl. This is stronger, not weaker: a compromised systemd cannot lie to it.
  2. User surfaces enumerate homes from the target's passwd, not $HOME. Unreadable or encrypted homes are coverage gaps.
  3. Network checks still work if the rescue environment has connectivity — queries concern the target's packages, not the live host.
  4. Strictly read-only against the target; reports go to --report-dir (INV-5).

ALPM_DB_VERSION (currently 9) is checked and an unrecognised value is a hard, documented refusal — a supported outcome on derivatives, not a surprise.

4.1 · The sync-DB name oracle fails open

Foreignness is !syncNames[pkg], so the name oracle is the one evidence source whose emptiness is indistinguishable from a confident answer. A .db that decompresses cleanly but whose entries do not match <name>-<ver>-<rel> yields zero names, zero gaps and a nil error — and every installed package is then classified foreign while the run reports complete coverage. That is the false-accusation analogue of the false-assurance failures INV-9 exists to prevent, and it is systemic rather than per-package.

The obvious guard — gap on any zero-name DB — is wrong: an empty repository is a legitimate state, and gapping it would manufacture false gaps on healthy systems. The rule is therefore structural, not numeric:

Every package entry in a sync database that does not yield a name is a coverage gap, and the gap records how many. Zero package entries is an empty repository and never a gap.

A package entry is a top-level directory entry in the database's tar, one per package. It is not a raw tar entry: each package contributes both a directory entry and a desc entry, so counting raw entries roughly doubles the denominator and makes the gap's count meaningless.

The distinction is what separates "this repo has nothing in it" from "I could not read this repo", and only the second is a gap. A consumer that sees such a gap must not report foreignness verdicts derived from that oracle as complete.

Corrected 2026-08-04, after the join lane's review. This rule first said "zero names but at least one entry". That is database granularity, and the failure is per entry: one parseable entry would declare a whole database understood, so a DB whose entries mostly fail to parse yields a non-empty name set, no gap, and every unparsed package silently reclassified as foreign — with coverage reported complete. Measured on the reference system, the original wording produced 5 false suspicious findings against pgp-validated repository packages while claiming full coverage. The count is load-bearing: a partial read is neither an empty repo nor a total failure, and only a per-entry accounting distinguishes it from either.

Hook directories: the system dir under /usr/share/libalpm/ (57 hooks here, active by default), /etc/pacman.d/hooks (absent on the reference system; HookDir commented out), plus any configured override. All must be watched.

5.1.1 · Name or pkgbase: the two halves are keyed differently

Added 2026-08-04. §5.1's critical rule is a conjunction — absent from the AUR index and cgit carries a tombstone — and this specification never said which subject either half is keyed on, nor required them to be the same subject. Three high-severity defects came out of that one omission, and all three were found only by running the tool. The rule:

  • Presence is keyed on the package %NAME%. The AUR RPC's arg[] matches package names, not bases — measured, and by=pkgbase is rejected outright by the v5 API. Asking by base means every split package whose base is not itself a package name reads as absent from the AUR, with coverage reported complete.
  • The tombstone is keyed on the %BASE% the installed package declares. cgit is organised by pkgbase; there is no per-name log.
  • Where a returned record's PackageBase and the installed %BASE% disagree, cgit must be consulted about the base the package declares — critical on a malware removal, a gap on lookup failure, and silent otherwise. This is not defensive pedantry: AUR names are freed when a base is removed, so a clean package can be republished under a name whose original base was tombstoned, while a user still carries the malware build. Keying presence on name alone reads that clean and complete.

The silent-otherwise case is deliberate. A benign rename produces exactly the same disagreement, so anything louder than silence would fire on ordinary packaging events.

Do not "fix" this by trusting %BASE%. It is builder-controlled. A package published nowhere can declare a healthy base, and if presence is keyed on the declared base it disappears from the sweep entirely — no finding, no gap, cgit never consulted. Both halves are needed precisely because each covers the other's blind spot.

5.3 Integrity

✎

pacman -Qkk already does the file-level work — full sha256 against mtree, backup file: prefixing, and %BACKUP% excluded from its altered count. This spec does not claim that as a novel capability. aurvet reimplements it only for what -Qkk cannot do: offline-root operation, parallelism, structured output, and correlation with other evidence. The genuinely novel layer is mtree-level tamper evidence (§8) — -Qkk trusts the mtree and structurally cannot detect its modification.

6 · Correlation

Findings carry correlation keys and clusters escalate. Three keys, because package scope alone cannot reach the persistence class — those files are unowned by definition, so there is no package to scope to:

  1. Package key — for evidence with an owner.
  2. Temporal key — evidence timestamps inside one window. All inputs already collected: mtree time=, %INSTALLDATE%, and [ALPM] transaction times. Timestamps must be parsed with explicit offsets; the reference log mixes two.
  3. Path attribution — resolve an unowned unit's ExecStart and match its directory or filename stem against foreign package names; and for anything installed after §7 is live, use the recorded set of paths that appeared during that install, turning inference into fact.
◆

Stated limit, in output as well as here (INV-6). Correlation does not survive a competent attacker. If a compromised package's build() emits the payload into its own $pkgdir and the package ships an ordinary-looking unit for it, then there are no unowned files, the mtree is self-consistent, and ExecStart resolves to a package-owned binary — every §5.4 check and the whole of §5.3 go silent. The host-side half of this tool catches sloppy malware. The real incidents were sloppy; they needn't have been. Provenance (§5.1) is what survives, which is why it leads the delivery sequence.

7 · Provenance capture — the ephemerality fix

Every §5.1 check depending on the helper cache or a retained artifact is unreliable long-term: 16 of 39 foreign packages (41%) already have neither, .BUILDINFO is archive-only, and 38 of 39 carry %PACKAGER% = Unknown Packager so there is no local fallback identity.

aurvet snapshot <pkgbase> records, into the tool's own state, the small artifacts that matter: PKGBUILD, .SRCINFO, .BUILDINFO, git log summary, remote URL, resolved source URLs, and the upstream commit actually built for VCS sources. A few KB per package against the 88 GB the cache occupies to hold the same facts.

Invoked automatically by review/install, and by a PostTransaction hook — which is what that hook is genuinely good for, unlike gating. Note PostTransaction hooks do not run when a transaction fails, so scan also opportunistically captures for any package whose evidence is still present but unsnapshotted.

Snapshots are keyed on pkgbase, not pkgname — 433 of 1409 installed packages are split, and a snapshot records what one build produced. Where no snapshot and no live evidence exist, checks report unavailable (INV-10) and the summary states it: "provenance unavailable for N of M foreign packages".

Scoped 2026-08-04. This sentence previously read as a blanket "keyed on pkgbase, not pkgname" for all provenance, and was cited that way. It is true of snapshots and false of AUR index presence, which is keyed on the package name because the RPC matches names — see §5.1.1. Read as a blanket rule it produces the defect §5.1.1 exists to prevent.

8 · Baseline & trust chain

Two layers, so the baseline stays small. It stores the hash of each package's mtree, not per-file hashes — those already exist in the mtree. File tampering is caught by the mtree; mtree tampering, the attacker's next move, is caught by the baseline. ~1409 records rather than ~325k.

Manifest — canonically serialised, sorted keys, no floats, fixed field order; sloppy serialisation makes signatures worthless and is the easiest thing here to get wrong. Contents: package identity + sha256(mtree) + sha256(install); provenance snapshot digests; surfaces inventory including all SUID/SGID; adjudications; and metadata recording tool version, host, root, active bundle version, and the earliest pacman.log timestamp so later truncation is itself detectable.

Chain and replication

A git repo of signed entries with prev_hash, each carrying a detached ed25519 signature over the canonical JSON — deliberately not git commit signing, which would couple the tool to the user's git config. Keys use the OpenSSH ed25519 format, so ssh-keygen, ssh-agent, and FIDO2 sk-ssh-ed25519 keys all work — INV-7 satisfied by hardware rather than discipline.

▲

The tamper-evidence claim must be stated precisely, because the reviewed design overclaimed it. "An attacker cannot rewrite history that exists on a remote" is true only if the remote forbids it. Push credentials necessarily live on the monitored machine, so a root attacker can force-push or delete. Therefore: an append-restricted deploy key, force-push and branch protection are load-bearing and must be documented as such, a second replication target is recommended, and the chain records pushed: bool with every run reporting unpushed entries prominently — an unpushed entry has none of the property the argument rests on.

Bootstrap

A first baseline asserts nothing about cleanliness. baseline init therefore runs a full scan and refuses to write while unresolved critical findings exist; each must be adjudicated with a recorded reason, converting an invisible assumption into a dated, signed, auditable one. It hard-refuses unprivileged (§11) and refuses a triage-tier scan as its basis (§13).

9 · Indicator bundle

✎

Named "indicator bundle", not "rules", deliberately. All non-trivial detection logic is compiled: ownership resolution, host comparison, tombstone corroboration, correlation, symlink handling. A network-delivered bundle can carry only data — host lists, patterns, digests, thresholds, known-bad names, the rebuild-repo list. That is what threat intel is, but calling it a rules engine would promise updatable detection capability the design cannot deliver. New detection logic ships with the binary.

Key hierarchy — TUF-lite, fully INV-1 compatible:

  • Embed an offline root key set (2-of-3, hardware-held). Root signs only a delegation document.
  • The delegation names short-lived (30–90 day) online bundle-signing keys with valid_until. Rotating the online key ships no new binary.
  • Bundles carry spec_version, a monotonic bundle_version, valid_until, and the digest of the prior bundle.
  • Anti-rollback floor lives in root-only state, never the cache. A bundle below the floor is refused.
  • Signature verified over raw bytes before parsing. Size cap, timeout, no cross-host redirects.
  • Bundles cannot introduce keys. Root rotation is out-of-band; a binary whose root set is retired fails closed with an actionable upgrade message.
  • On expiry, degrade to coverage-incomplete — never report clean. Report the active indicator count so a suspicious drop toward zero is visible; a signed bundle that removes detections is an attack.
  • Never auto-update. --version prints root fingerprints, delegation expiry and cached bundle version.

A separate RULES-CHANGELOG tracks bundle versions with a rationale per change, and every finding records the bundle version that produced it.

10 · Pre-install gate

◆

A pacman hook cannot be the gate. By the time pacman sees a built package, makepkg has already run prepare(), build() and package() as the invoking user — the build-time-fetch vector has already fired, and the hook cannot see a PKGBUILD at all.

aurvet install <pkg> is the gate. It clones the AUR repo itself, resolves the full AUR dependency closure and reviews every new PKGBUILD in it (the attacker's move is a benign package pulling a malicious dep), prints the tree, snapshots provenance (§7), and only then hands the vetted directory to the configured helper.

Approval keys on pkgbase + PKGBUILD digest, so it is silent when nothing changed and re-prompts on a recipe change. For VCS packages — whose PKGBUILD is stable while the source moves every build — it shows the upstream commit range since the recorded snapshot, so the operator reviews the delta rather than an unchanged recipe. Review output leads with indicator hits and a diff against the last approved PKGBUILD, not the whole file; scriptlets are visually flagged, being rare (7 of 39).

Hook integration, two roles, neither of them gating the build:

  • PostTransaction — provenance capture (§7). The hook's genuine strength.
  • PreTransaction — a narrow, time-budgeted provenance check on incoming targets (.BUILDINFO, scriptlet, approval status). Shipped inert and warn-only: AbortOnFail is required for a non-zero exit to abort anything and is opt-in by one line. Exec must route through a path that always exists and no-op when the binary is absent, so removing aurvet cannot brick pacman. Note hooks receive matched trigger targets — package names for Type=Package, paths for Type=Path.

The enabled hook is a symlink into a package-owned path, and the ownership oracle resolves symlinks — so aurvet does not flag its own hook, and does so without a name-based exemption an attacker could imitate.

11 · Config, state, and process model

Resolution order: --flag > environment > system config > user config > compiled defaults.

◆

When euid == 0, never read user config or user cache, and ignore $HOME and SUDO_USER entirely for trust-bearing paths. Otherwise an unprivileged local attacker controls what a root-privileged security tool trusts — bundle path, cache location, public key. Refuse any config or key file that is group- or world-writable or not root-owned, and say why. A user config may tighten but never loosen system settings.

Privilege policy. Measured: 25 package-owned files are unreadable and 229 directories unlistable unprivileged — so under INV-3 an unprivileged scan could never exit 0, and users would learn to ignore the exit code. Therefore scan requires root and refuses unprivileged unless --allow-degraded is passed, which stamps the report and forces the incomplete exit. baseline hard-refuses unprivileged: a baseline blind to 229 directories blesses whatever hides in them forever.

11.1 Staged privilege — the privileged phase contains no parsers

The tool's job is parsing attacker-controlled input while needing to read root-only files. Those two requirements are separated in time rather than accepted together.

Implementation status, v0.0.1: this table describes the design, and the build satisfies it only in part. Recorded here rather than in a commit message because a specification that overstates its own implementation is the manufactured confidence this document spends eighteen sections refusing.

What holds. The integrity path obeys the table. internal/collect learns which paths a package records from the plain-text files list — a newline split, no decompression and no field interpretation — opens and hashes them while CAP_DAC_READ_SEARCH is held, and internal/check then compares with no I/O at all. The gzip decompression and the mtree grammar, the two genuinely dangerous parsers in that path, run after the reads. The local desc/files parse is likewise fed from phase 1's buffers, so the database is read once rather than twice.

What does not. Phase 2's “must not read anything not already buffered” is not true today. Four readers still run while the capability is held: the sync database's tar+gzip reader, internal/surfaces (hooks, units, wants, per-user), internal/own's lazy per-component symlink resolution, and internal/correlate's stats. The capability is dropped at the end of the scan rather than immediately after collection.

Why, structurally — this is not an unfinished task. Phase 1 buffers by path, and three of those four readers probe paths that are the output of a parse. HookDir is discovered by parsing pacman.conf and following its Include directives, and it may name an arbitrary path, so no enumerable superset of it exists — the honest statement is that a phase forbidden to parse cannot know which directories pacman reads. A unit's ExecStart= target is the parsed value of a directive, and the case worth detecting is precisely a path no package records, so the recorded-path list cannot contain it. Ownership resolution and correlation then take those paths as their input.

The only general fix is for phase 1 to enumerate metadata for the whole root at every tier — what Sweep already does at paranoid. Measured on the reference system that sweep raises 22 coverage gaps full does not have, taking full from 72 to at least 94, and it would redefine the tier: §13 assigns the unowned walk to paranoid and to no other. That is a tier-semantics change, so it is deferred rather than taken quietly.

What this costs, stated plainly. A bug in the hook parser, the unit parser, the correlator or the sync-database reader is reachable while the process holds a read capability, in a process that later makes network requests. The capability is read-only, PR_SET_NO_NEW_PRIVS is set and nothing can be regained, so such a bug cannot write or escalate — but it could read what the scan was entitled to read. That is a smaller exposure than the design admits and a larger one than the table implies.

To close it, either §11.1 gains a stated exception permitting phase 1 to extract directory names from a plain-text configuration file — the argument this build already makes for files — or hook-directory discovery stays privileged and the drop moves only as far as the remaining readers allow.

Feasibility is measured, not assumed: phase 1 buffers ~41 MB on the reference system — 16.2 MB compressed mtree, 24.1 MB files, 0.7 MB desc, 0.4 MB surface files. Decompression to 62 MB happens after the drop. Hashing 19.8 GiB needs no buffering, only a streaming digest, and sha256 over a byte stream is negligible attack surface. Phase 1 therefore contains syscalls and a hash function, nothing else — a parser bug is an unprivileged bug.

◆

No file capability on the binary. Arch precedent exists — btop ships cap_dac_read_search,cap_perfmon=ep — but it does not transfer: explain surfaces matched bytes, so a world-executable cap_dac_read_search binary would be an arbitrary-file-read oracle for /etc/shadow. Privilege arrives per-invocation via sudo or a systemd unit, never from the filesystem.

11.2 TOCTOU-safe I/O — open then fstat, never stat then open

stat-then-open resolves the path twice, and the window between resolutions is the vulnerability. The operation is inverted:

  • Open once with O_NOFOLLOW|O_NONBLOCK, fstat that fd, verify S_ISREG, and hash from the same fd. One resolution, no window.
  • Every open is confined via os.Root (Go 1.24+; Arch ships 1.26.5) so no path component can be swapped for a symlink escaping the tree. This matters most under --offline-root, where the whole tree is attacker-controlled.
  • O_NONBLOCK plus the S_ISREG check is not incidental: a packaged path replaced by a fifo would hang the scan, and one aimed at /dev/zero would stream forever. Both are denial-of-tool with no panic involved.
  • Re-fstat the same fd after hashing. If st_ino/st_dev/st_size/st_mtime moved, emit mutated during scan — a signal, not a nuisance.
  • The triage prefilter is itself the TOCTOU pattern (stat, decide, maybe hash), so its stat must come from the fd it would hash. That costs an open per file even when the hash is skipped — the same order as the measured 0.24 s stat sweep, so still sub-second, and it deletes the race rather than documenting it.

11.3 Panic and hang containment

  • Per-subject recovery boundary. Each package and each surface file is analysed inside a unit with a deferred recover; a panic becomes a could-not-analyse coverage gap under INV-9, attributed to that subject. Without this, one crafted package aborts the scan and thereby hides every other package — which is the actual attack.
  • Every worker goroutine needs its own deferred recover at its top-level function. In Go a goroutine panic cannot be recovered by its parent, so without this the per-subject boundary is decorative.
  • A recovered panic is never silent: it emits the coverage gap and auto-writes a reproducer bundle (§12), because a panic on attacker-controlled input is simultaneously a bug and a possible exploitation attempt.
  • Hangs outrank panics, because recover does nothing for them. Bound everything: per-subject context timeout, decompression ratio and absolute caps, max mtree entries, max tokeniser recursion depth and token count, GOMEMLIMIT with bounded in-flight work.
  • Any recovered panic or timeout forces coverage-incomplete — exit 3, never 0.

11.4 Concurrency

Concurrency. An advisory lock on the state dir; and pacman's db.lck is detected — scan warns and records it, baseline append refuses, since reading a half-written DB during a transaction produces spurious findings that would otherwise get signed. All state writes are temp + fsync + atomic rename; a payload without a valid signature reads as absent, not as corruption.

12 · Findings & adjudication

Fingerprint = sha256(rule_id ‖ subject_kind ‖ subject_identity ‖ scope_class), where subject_identity is deliberately version-independent — package name, not name-version; the path, not its digest. With ~28 transactions/day on the reference system, a version-bearing fingerprint would re-alert everything on every upgrade.

ScopeBehaviour
pinThis exact evidence digest; auto-expires on any change and reappears once.
subjectThis rule × this package/path; survives upgrades.
ruleThis rule everywhere; requires --force and is echoed in every subsequent run header.

Indicators carry a fingerprint_epoch: a change to matching semantics bumps it, and suppressions bound to a prior epoch surface as stale — re-adjudicate rather than silently persisting or silently vanishing. Severity or wording changes do not bump it. Adjudications require a reason and expire (default 180 days); dead suppressions that match nothing are reported for removal.

Three weights, not two — the reviewed design had no middle ground, so users would over-suppress or ignore output:

  • triage ack / snooze / note — lightweight, local, unsigned, expiring.
  • Signed adjudications — reserved for baseline init, where they belong.
  • Reports persisted unconditionally, with scan --since-last printing only new and resolved findings. This is the command people run daily and it needs no keys at all.

explain gives the rationale, the matched pattern with byte offsets, the rules that did not match on the same subject (missed detections are debugged from non-matches), what the finding cannot prove (INV-6), copy-pasteable investigation commands, and a clearly separated "if this is real" paragraph. bundle <fingerprint> emits a redacted, self-contained fixture root reproducing the finding — which costs almost nothing because offline-root already exists, and makes every false-positive report a test case.

15 · Testing

Eight suites. Suites 2, 3 and 7 are what decide whether the tool is trustworthy.

  1. Collector units against synthetic fixture roots — fake local DB with real gzipped mtrees, fake unit dirs, fake caches. No root, no containers, no VMs.
  2. Incident-shaped acceptance fixtures reproducing the CHAOS RAT and acroread structural patterns; must yield a correlated critical cluster. Inert markers only — no working payloads, no real C2 addresses.
  3. False-positive corpus — release gate (INV-8), and it includes system state. Three fixtures: a stock install root, a cruft-laden root (pip, npm -g, manual /usr/local, hand-written units), and the pinned PKGBUILD corpus. All must yield zero criticals. The PKGBUILD corpus is pinned by pkgbase + commit sha + content digest and asserted over token-stream digests rather than stored source text — which sidesteps redistributing unlicensed PKGBUILDs entirely and keeps diffs reviewable.
  4. Canonicalisation and signing properties — sign, flip any single byte, verification must fail; reordering map keys must not change the digest. Chain tests: truncated, forked, replayed, wrong prev_hash all rejected.
  5. Coverage honesty — asserts the measured reality: an unprivileged scan of a stock root yields a stable gap count and the incomplete exit, never 0.
  6. Offline-root equivalence — identical findings modulo the four deltas enumerated in §3.
  7. mtree conformance — the full vis(3) escape set, /set//unset inheritance, float timestamps, ./. metadata entries, md5digest, symlinks, hardlinks, missing #mtree header, truncated gzip, decompression-ratio caps, and traversal rejection. Cross-validated against pacman -Qkk on a fixture root.
  8. Process-model assertions (§11.1–11.3), because these mechanisms fail silently when broken: after the transition, an attempt to read a root-only file must fail — proving the drop is real and irrevocable; the built binary has no DT_NEEDED/PT_INTERP; a fixture whose packaged path is replaced by a fifo and by a symlink escaping the root must be refused rather than hanging or following; a file mutated between hash and re-fstat must yield mutated during scan; and a deliberately panicking subject must produce a coverage gap with the rest of the scan completing plus exit 3 — including when the panic originates in a worker goroutine.
  9. Parser robustness fuzzing — several thousand real PKGBUILD/.SRCINFO pairs asserting panic-free and hang-free, not correctness. The input is attacker-controlled, which is INV-2's own justification. Filesystem edge cases belong here too: hardlinks, sparse files (which defeat a size prefilter), immutable files, xattrs and ACLs (not covered by mtree at all — either checked or declared a non-goal), btrfs subvolumes and --one-file-system truncation, overlayfs, and mid-scan mutation detected by re-stat after hashing.

Network access sits behind an interface with recorded fixtures; no test touches the network. A -tags=live smoke test runs against the real system, outside CI.

16 · Packaging & distribution

Build

CGO_ENABLED=0, static, -trimpath, -mod=vendor, -buildvcs=false, options=('!strip'), one merged -ldflags. This is a deliberate documented deviation from Arch's Go guidelines, which mandate -buildmode=pie -linkmode=external and therefore CGO and dynamic linking.

Dependency policy (D-1, D-3). golang.org/x/sys is the project's only sanctioned third-party dependency, entering at P1-B for capset/prctl — the privilege boundary is the wrong place to hand-roll syscall structs. Git history is read by parsing objects with the standard library rather than executing git against an attacker-controlled repository. All dependencies are vendored, so build() performs no network fetch and the project's own PKGBUILD passes the project's own rules.

◆

The deviation is load-bearing: a dynamically-linked aurvet can be subverted by LD_PRELOAD or /etc/ld.so.preload before it can report on /etc/ld.so.preload — a check this tool rates critical. Mitigations: a PKGBUILD comment stating the reason, a test asserting no DT_NEEDED/PT_INTERP in the built binary, and sanitising LD_*/GLIBC_TUNABLES with a re-exec at startup. Namcap warnings are suppressed explicitly, never silenced. Note GOFLAGS -ldflags is replaced, not merged, by a command-line -ldflags — naïve version injection silently changes the link mode.

Reproducibility is the answer to the bootstrapping paradox

A tool warning about unvetted AUR packages would itself arrive as one, and its AUR account is the highest-value takeover target available. Reproducible builds convert "trust me" into "check me", which is the only credible position here:

  • Pinned Go toolchain (toolchain in go.mod, GOTOOLCHAIN=local), vendored deps, SOURCE_DATE_EPOCH — never an injected build date; inject version and commit only.
  • strip is on by default and runs after the build, so the packaged binary would not be the one signed. Resolved (D-2): options=('!strip') — reproducibility is defined over the binary itself, so verify-self works and a user can check a published hash without rebuilding a package.
  • CI builds on two runners and diffs; publish SHA256SUMS and a verify-reproducible target.
  • A second OpenPGP identity for release artifacts, because makepkg only understands OpenPGP (validpgpkeys) — ed25519 alone gives AUR users no verification path. Fingerprint published in several independent places.
  • Publish the canonical PKGBUILD upstream and have scheduled CI diff the live AUR copy against it — self-defence against takeover of your own package.
  • Register the plain, -bin and -git AUR names on day one, or someone else supplies the "convenient binary build" of your security tool.

Packages and files

The source package is canonical — a -bin asks users to trust a build machine, which is the trust this tool exists to question; if shipped, it carries options=('!strip') so its hash matches the signed artifact. Release tarballs are git archive assets, never GitHub's auto-generated archives (whose checksums are not contractually stable, and which contain LFS pointers rather than content). aurvet's own PKGBUILD must pass aurvet's own indicators as an automated release gate — note that without vendored deps, build() performs a network fetch and trips its own critical rule.

Installed: man pages (authored in scdoc; zipman is on by default so install uncompressed), shell completions for bash/zsh/fish with a test asserting no rot, the inert hook, timer units with PrivateNetwork=yes on the scan unit and network only on the update unit, tmpfiles.d entries, SPDX license=(). Helper support is optdepends only — never a hard dependency. arch=('x86_64' 'aarch64'), cross-compiled in CI, with a published supported-platform matrix stating the derivative caveats.

SECURITY.md is two-sided. Inward: private reporting, coordinated disclosure, and an in-scope list that explicitly names false negatives — a false clean, a verification bypass, an evasion — as vulnerabilities, because saying so invites the reports the project needs. Outward: docs/reporting-malware.md for what an operator does when a finding is real, linked from critical explain output. Plus a privacy statement: update and AUR queries disclose IP, version and the set of installed foreign package names; honour proxies, offer --no-network, never auto-update, no telemetry.

CI hygiene, non-negotiable for this project: go vet, staticcheck, govulncheck, go mod verify, gosec, namcap on the built package, a clean-chroot build from the tagged tarball before any AUR push, .SRCINFO asserted in sync, and every CI action pinned by commit SHA, not tag — a supply-chain tool consuming mutable refs would be called out, correctly.

18 · Known limits

Stated in tool output, not only here (INV-6).

  • A malicious build whose payload lives only in its own package files is undetectable by integrity or surfaces checks. The mtree came from that build; the hash is the malware's. Only provenance can reach it. This is the design's central blind spot and §6 spells out how ordinary it is to exploit.
  • An attacker with root before the first baseline wins — everything blessed is assumed-good. Mitigated only by the bootstrap refusal recording what was waved through.
  • Upstream source malice is out of scope. A clean PKGBUILD fetching a genuinely backdoored release passes.
  • A trigger-activated payload that has not yet acted leaves no trace to find.
  • %VALIDATION%, "foreign", and cache-derived provenance are all config-dependent. A local repo of self-built AUR packages yields zero foreign packages while running entirely unreviewed code; doctor warns when non-official repos are configured.
  • Static analysis cannot resolve dynamically constructed code — INV-9 makes that visible rather than silently clean, but it does not make it analysable.
  • xattrs and ACLs are not covered by mtree, so an ACL-granted read on a root-owned binary is invisible unless explicitly checked.
  • The staged privilege drop protects the parsers, not the collector. A bug in phase 1 — the directory walk, the confined opens, the digest loop — still runs with CAP_DAC_READ_SEARCH. That surface is deliberately tiny (syscalls plus a hash function, no parsing) but it is not zero, and nothing here defends against a kernel bug.
  • Phase 2 cannot re-read. Anything the collector did not buffer is unavailable to analysis for that run, by construction. A future check needing evidence phase 1 doesn't gather requires changing the collector, not just the analyser.
